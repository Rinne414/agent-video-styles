## Skill gaps

1. `skill/references/styles/code-terminal-walkthrough.md`, "Structure" and "Motion grammar" (zoom). The structure table is for 45 s with a Problem beat that the brief ("3 steps" tutorial) does not have, and the zoom `1.0 -> 1.15` onto a block collides with the step label above the window (HyperFrames `check` flagged `content_overlap`: the scaled tab bar ran under the pill). Proposed edit: add "Tutorial variant (20-40 s, no old code): Hook 8% (result peek), one step per install/type/diff 12-35% each, Run 35%, Outro 6%" and "Zoom about the window's top edge (transform-origin at the top center) and cap at 1.10 so the window never grows into the step label or off the canvas; the 1.15 value only fits when the label is inside the zoomed layer."
2. `style file`, "Look" table. No terminal row count or window-clip guidance: with a 776 px body and 42 px rows a half row shows under the title bar. Proposed edit: "Terminal: clip rows in a box of exactly N x line-height (17 rows at 28 px / 1.5), vertically centered in the body, so scrolled rows never show a partial line."
3. `style file`, "Pitfalls" / "Inputs". Missing: the capture trap on Windows. `curl -w "%{http_code}\n"` in Git Bash writes CRLF, so the captured lines ended in `\r`; a strict regex used for coloring silently failed on every line except the last (rows rendered gray). Proposed edit: "When capturing real output on Windows, strip `\r` before putting it in content.json (`tr -d '\r'`)." Also: "Pick an unusual port (port 3000 was already taken by another process here and returned 401)."
4. `style file`, "Inputs to ask for": "the real before/after code (compile- or run-checked)" does not say how the current library API is verified. For express-rate-limit v8 the option is `limit` (v6 and older used `max`), the export is `{ rateLimit }`, `standardHeaders` accepts `'draft-8'`. I verified by running it. Proposed edit: "For library snippets, install the pinned latest version in `out/` and run the snippet; print the version in the README. Use context7 for the API if an agent cannot run it."
5. `skill/references/tools/hyperframes.md`, "Content-driven template" and "Determinism". The doc covers audio-driven templates but not a text-driven typing/terminal template, which needs: per-character reveal times as data attributes, a proxy tween `onUpdate` driver, caret/scroll computed from time, and generic `fromTo` tween lists. Proposed edit: add a short "Typing/terminal pattern" with the build script emitting `<i data-t="1.234">c</i>` per character plus one `tl.fromTo(proxy, ... onUpdate: () => apply(proxy.t))`, noting `immediateRender: false` on every chained `fromTo` of the same property (otherwise the last tween's `from` wins at t=0). I used it and it rendered correctly.
6. `hyperframes.md`, "Check, then render". Add the checks that fire on code/terminal compositions: `content_overlap` for scaled windows near fixed labels, `canvas_overflow` infos for scrolled-off terminal rows (fix: `data-layout-allow-overflow` on the rows container, which I did not apply), and that `snapshot` leaves `snapshots/` and `descriptions.md` (git-ignored at the repo root, but the folder cannot be removed by some sandboxes; `rm -rf` was denied in this session).
7. `hyperframes.md`, "Windows pitfalls hit". The note "Git Bash heredocs holding several long files failed with unexpected EOF" is accurate: it happened again (a CSS plus JS heredoc batch). Proposed edit: promote it to the first line of the Windows list ("write source files with the editor tool, never heredocs; Python heredocs for small edits are fine").
8. `hyperframes.md`, Fonts. It says Inter auto-resolves from Google Fonts at first use (network). For a template that must render offline the doc should show the `@fontsource` route that worked here: `@fontsource/inter` and `@fontsource/jetbrains-mono` woff2 files copied to `assets/fonts/`, declared with `@font-face` (weights 400/700 and 600/800, 96 KB total, `check` passed, glyphs verified in stills). Proposed edit: add that snippet next to the CJK one.
9. `hyperframes.md`, render notes. The render printed "A frame failed verification, so parallel drawElement capture fell back to the screenshot path and is now off for this install" and rendered with 5 workers in screenshot mode (1 min 22 s for 35 s, slower than the "0.7 s per second" estimate: 2.4 s per second under parallel load). ## Honest self-assessment
- Does it look like the style description? Largely yes: `#0D1117` canvas with radial lift, 1400x820 window with traffic dots and a filename tab, `github-dark` highlighting, JetBrains Mono 30 px at line-height 1.5, 64 px gutter with dim line numbers, focus band and 30% dimming, green added-line background with a green `+`, blue pill callouts with leader lines, `#010409` terminal with green `$` prompt, 2 chars/frame typing, 1.5 chars/frame commands, 10-frame pause, caret hidden while typing, 8-frame focus fades, 20-frame zoom. Not done: a Problem beat with red removed lines (the brief has none), a true FLIP token morph (the diff is pure addition, so lines expand and neighbors slide), spinner cycles, and key-click audio (the brief says silent). The zoom is 1.10 instead of 1.15 for the layout reason above.
- What a motion designer would criticize: (1) the scene cuts are quick fade-outs rather than a designed transition, with a brief dip to canvas between scenes; (2) the terminal flood of 95 lines at 1 line per frame is unreadable by design but may feel abrupt, and a short ease-in of the rate would be nicer; (3) the hook is typographically strong but static in composition (no real camera move) and the peek panel is a stack of three lines, not a convincing terminal; (4) the outro is a plain centered card, not a branded end frame; (5) the 3% camera drift is nearly invisible and only keeps frames alive; (6) the install scene leaves most of an 820 px window empty (a shorter window would be tighter); (7) typing has no key-click sound or per-line rhythm variation, so it feels mechanical; (8) the badge sits outside the window at the top right and was not tied to the 429 rows with a leader line.
