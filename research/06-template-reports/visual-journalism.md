## Skill gaps

1. **`references/styles/visual-journalism.md`, Motion grammar > Highlight.** The recipe says measure `Range.getClientRects()` at build time. In HyperFrames the build runs outside the browser and fonts load asynchronously, so a sync measurement in the inline script is unreliable. What worked: an inline `<mark>` with a wobbly SVG as `background-image`, tweening `background-size` from `0% H` to `100% H`. It sits exactly behind the words, wraps on its own, and needs no coordinates. Proposed edit: replace the measurement advice with this recipe, and add `white-space: nowrap` for multi-line phrases (a wrapped mark animates all fragments at once).
2. **Same file, Pitfalls (missing).** The HTML `<mark>` element has a UA default `background-color: yellow`. With `background-size` below 100% the whole inline box shows pure `#FFFF00` outside the wipe, and it looks like a blend bug. Add: set `background-color: transparent` on the highlight class. I lost one snapshot round to this.
3. **Same file, Motion grammar > Camera.** Push to 1.05 with a 96 px safe area: at the end of the push, an element at x=96 sits at about 54 px. State the rule (keep text at least 140 px from the edge, or push 1.03).
4. **Same file, Motion grammar > Annotation.** The recipe says "dashed line draws via `stroke-dashoffset`". That does not work for a dashed line (the dash pattern uses `stroke-dasharray`). What works: a duplicate path in an SVG `<mask>` (`maskUnits="userSpaceOnUse"`, white stroke, `pathLength=1`, dasharray `1 2`) whose dashoffset is tweened; the visible path keeps the 14/10 dashes. Also the mask must not use objectBoundingBox, because a perfectly horizontal line has a zero-height bbox. Add this snippet.
5. **Same file, Structure and the brief.** The structure table is for 60 s and the style says 45-120 s; the brief asked for about 35 s. There is no guidance for compressing it (I used 7 scenes, no separate "context" pair, cutting each evidence scene to 4-6 s). Proposed edit: add a short-form table (30-40 s: hook 5 s, 4 evidence scenes of 4-6 s, close 5 s) and say that the 6 s minimum for evidence scenes only applies to 120 s videos.
6. **Same file, Look > Source tag.** Fixed text `SOURCE: <name>, <license>, <short id>` is unfit for a code-drawn illustration that illustrates a fact from a source. I used `ILLUSTRATION. Context: <author, work>` and `SOURCE: <author/work>` for cards that restate a cited fact. Add a rule: a tag naming a source must correspond to a ledger entry, and the ledger should note when a figure is quoted second-hand (here McLean's estimate via Rodrigue).
7. **Same file, Quality bar.** "At most 3 elements move at once" conflicts with the motion grammar (3 cards entering, drift on every card, camera push, plus highlights and dashed draws). Define what counts (cards only? any tween?) or loosen it.
8. **`references/tools/hyperframes.md`, Content-driven template.** Good, but missing: how to resolve per-word cues (I added `data-cue="word"` resolved at build time to `data-t`, with a loud failure if the word is missing), that one TTS token can contain several words ("April 26, 1956" came back as ONE token because the service merges dates; the cue must match the first word), and that `fromTo` on `svgOrigin` needs `svgOrigin` in both the from and to vars or the first frame uses the wrong origin (the bars rendered offset in the first still). Proposed edit: add these three notes.
9. **`references/tools/hyperframes.md`, Check, then render.** Mention the `data-layout-allow-overlap` / `data-layout-allow-overflow` attributes in the recipe (the style file mentions only overlap) and that the `check` output for `text_occluded` fires when a source-tag pill covers diagram text (keep a 70 px footer in cards).
10. **`references/audio-tts-captions.md`, Pacing.** The 2.4 words/s guidance for AndrewNeural does not hold for `en-US-GuyNeural`: 11 words took 5.2 s (about 2.1 words/s with trailing silence) at +0%, and a 91-word script ran 37.6 s. Add a per-voice table, and say that a number or date in digits (`58`, `1956`, `April 26, 1956`) is one TTS token, so the cue must match that token. I needed one regeneration to land near 35 s (final rate +8%, 3 sentences shortened).
11. **Online verification (not in the skill).** I had to search the web to verify the container facts (voyage date, cost per ton, trade effect). The sources disagree on the cost ($5.83 vs $5.86 per ton, Rodrigue vs Wikipedia) and one search result gave a working-paper figure (about 700 percent over 20 years) that differs from numbers I half-remembered (790 percent), so I dropped the number. Proposed edit: in the style file's brief template add "fact ledger must record the figure's exact wording and edition", and add a pitfall "do not quote economics numbers from memory; working papers and published versions differ".

## Honest self-assessment

Does it look like the style? Partly. It has the dark ground, cream cards, serif headlines, marker highlights, dashed annotations, source pills and a source-list close, and the motion grammar is followed. It does not look like real Vox output: without photos or cut-outs the "halftone cut-out" and "red mark behind a cut-out" parts are missing, the diagrams are flat vector (clean, a little clip-art-like), and the grain overlay at 5 percent is hardly visible. The vignette and paper-grain tokens are in place but subtle. Layout is a repeated "big card plus side card" pattern that gets monotonous across 7 scenes. The final headline highlight on the ground is a duller gold than the marks on paper (85 percent alpha over near-black).

Is the recipe strong enough for others to reuse? Mostly for look and motion tokens (colors, type sizes, card entrance, highlight frames all transferred directly). The weak points are the ones in "Skill gaps": highlight placement method, dashed draw-on, and how to compress the structure to short videos. An agent following the recipe literally would hit the `<mark>` default background and the dashoffset-on-dashes problem. With gaps 1, 2, 4 and 8 fixed, an unattended run should land in one or two render passes.
